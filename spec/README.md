# 仕様

各フレームワークは、この仕様どおりに動く小さなサーバーを実装します。
仕様書とテスト(`tools/conformance/`)が食い違った場合は、**テストを正**とします。

## 共通の約束

1. 3000番で待ち受ける

2. データはメモリ上に置く(データベースは使わない)。再起動で消えてよい

3. 入力チェックは、そのフレームワークのおすすめのやり方で行う

4. 1つのプロセスで動かす(複数並べる仕組みは使わない)

## 扱うデータ: タスク

| 項目 | 型 | 説明 |
| --- | --- | --- |
| `id` | 整数 | 1 から順に自動で振る。削除した番号は使い回さない |
| `title` | 文字列 | 1文字以上 |
| `done` | 真偽値 | 完了したかどうか |
| `createdAt` | 文字列 | 作成日時。`2026-09-27T05:00:00.000Z` の形(JavaScript の `Date#toISOString()` と同じ) |

返事には、この4項目**だけ**を入れます。送られてきた余計な項目は無視します。

## 入口

| 操作 | 入口 | 送るもの | 成功 | 失敗 |
| --- | --- | --- | --- | --- |
| 作成 | `POST /tasks` | `title`(必須)、`done`(省略可、省略時は `false`) | 201 とタスク | 入力不正 400 |
| 一覧 | `GET /tasks` | なし | 200 と全タスクの配列(`id` の小さい順) | — |
| 1件取得 | `GET /tasks/:id` | なし | 200 とタスク | 無い 404 |
| 更新 | `PUT /tasks/:id` | `title`、`done`(どちらも必須) | 200 と更新後のタスク | 無い 404、入力不正 400 |
| 削除 | `DELETE /tasks/:id` | なし | 204(中身なし) | 無い 404 |

1. 成功時の返事は JSON(`Content-Type: application/json`)。ただし削除の 204 は中身なし

2. 更新しても `id` と `createdAt` は変わらない

3. 「入力不正」は次のどれか: `title` が無い・空・文字列でない、`done` が真偽値でない、中身が JSON として読めない。作成と更新の両方に当てはまる

4. 型の自動変換はしない。`"true"` や `1` を真偽値として、`1` を文字列として受け付けてはいけない(フレームワークの初期設定で変換される場合は切る)

5. エラーのときの返事の中身は自由(番号だけ確認する)

6. 次の場合の動きは決めない(テストしない): 数字でない `id`、「無い番号」と「入力不正」が同時に起きた更新、`Content-Type: application/json` 以外で送られた中身、`__proto__` や `constructor` という名前の項目
